# Templates (Phase 6)

`templates/<name>/theme.ts` is a **starting point** — design tokens, motion intensity, and a
suggested/avoid component list per art direction — not a finished design. The spec is explicit
about this: "Templates should supply structure and useful components without forcing every
client into the same appearance." A single-app repo can't ship six fully-built sites without
massive duplication, so what's real here is the decision layer Phase 7's `create-project` (not
built yet) will read from, and what a human or Claude Code reads before composing an actual
layout for a brief.

```ts
import { getTemplate } from '../templates'

const theme = getTemplate('luxury')
theme.colors.accent        // '#d4af37'
theme.suggestedComponents  // ['src/animations/ScrollReveal', ...]
theme.avoid                // things that fight this direction's intent
```

Six directions, each with genuinely different tokens and guidance — not the same site in six
colors:

| Template | Motion | Leans on | Explicitly avoids |
| --- | --- | --- | --- |
| `cinematic` | maximal | ScrollSequence, Parallax, HorizontalScroll, 3D | bright palettes, dense copy |
| `luxury` | minimal | ScrollReveal, Parallax, 3D | HorizontalScroll, bouncy eases |
| `editorial` | moderate | TextReveal, ScrollReveal | 3D, ScrollSequence |
| `ecommerce` | minimal | BeforeAfterSlider, 3D | HorizontalScroll, ScrollSequence, long reveals |
| `creative` | maximal | HorizontalScroll, TextReveal, Parallax | centered safe layouts |
| `immersive` | maximal | ScrollSequence, 3D, Parallax, HorizontalScroll | dense text, skipping reduced-motion |

Verified with a script that loads all six via `getTemplate()` and confirms each has a complete
theme (colors, fonts, motion profile, non-empty suggestions) and that an unknown name throws
rather than silently returning `undefined`.

## New reusable components this phase added

All four are demonstrated live in `src/App.tsx` (not just written and left unused) and verified
via a running dev server plus a production build:

- `src/video/ScrollSequence.tsx` — canvas-based scroll-scrubbed WebP sequence, driven by
  `src/video/scrollSequenceMath.ts` (pure frame-index/preload-window math, unit-verified with
  real assertions — see that file). Preloads a window of frames around the current one, skips
  drawing an unloaded frame rather than flashing blank, cleans up its scroll/resize listeners on
  unmount, and freezes on frame 1 under `prefers-reduced-motion`.
- `src/effects/Parallax.tsx` — GSAP `scrub: true` vertical drift, no-ops under reduced motion.
- `src/effects/HorizontalScroll.tsx` — GSAP ScrollTrigger pin + horizontal translate; under
  reduced motion, panels stay in normal (non-pinned) horizontal flex flow instead of animating.
- `src/effects/TextReveal.tsx` — per-word stagger reveal on scroll into view; renders plain
  fully-visible text under reduced motion.
- `src/effects/BeforeAfterSlider.tsx` — pointer- and keyboard-operable comparison slider, pure
  React/CSS (`clip-path`), no animation library dependency.

`public/demo-sequence/` is a 20-frame, ~88 KB synthetic WebP sequence generated by this repo's
own `npm run extract-frames` from an `ffmpeg testsrc` pattern — not stock footage, not a client
asset, purely so `ScrollSequence` has something real to scrub in the demo. Replace it (or
`App.tsx` entirely) when starting an actual client project.
